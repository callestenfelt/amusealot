Fix these first

Ordered by blast radius × likelihood, across all three areas.

  1. A failed send still reports success.send_newsletter.py exits 0 even when every send errors (e.g. revoked Resend key) — the ERR trap never fires and the admin gets a success email saying "0 email(s) sent". One sys.exit(1) when sent == 0.
  2. Dry runs aren't dry.A no-flag run_newsletter.sh still registers a real edition row, overwrites latest_news.json, and writes an archive file (step 6 ignores --apply); and collect_news.py saves the ETag cache in dry-run, so a Tuesday test run makes Wednesday's real run skip those feeds via 304 and permanently miss articles.
  3. Silent partial pagination disables dedup and sources.Both get_existing_hashes() and get_active_sources() swallow mid-pagination errors and return partial sets — a Baserow blip mass-duplicates articles or quietly empties the news section. Abort loudly instead, like the GitHub collector does.
  4. Unstable dedup hash duplicates date-less articles weekly.The content hash includes published_date, which falls back to today when a feed omits pubDate — same article, new hash, every Wednesday. Hash on URL (or title+URL) only.
  5. Rate limiting is one shared bucket behind Caddy.Limits key on remote_addr = the proxy's IP, so "10 subscribes/hour" is site-wide: one bot locks out every real visitor, and the per-IP defense is void. Add ProxyFix + forwarded client IP in Caddy (and strip client-supplied headers).
  6. Verify FORM_SECRET is set in production.The per-process fallback means every restart (or multi-worker gunicorn) silently invalidates rendered forms — visitor sees "Check your email", nothing is stored or sent.
  7. GET /unsubscribe is destructive.Corporate link scanners (SafeLinks, Mimecast) follow GETs in delivered mail and silently unsubscribe real readers. Render a confirm page on GET; unsubscribe on POST (RFC 8058 one-click already POSTs).
  8. Reminder email violates the dark-mode rule.The CTA splits background-color (on the <td>) from color (on the <a>) — exactly the pattern CLAUDE.md bans, risking an invisible confirm button in Word-engine Outlook dark mode.

Cross-cutting themes

Four patterns recur across all three areas — fixing the pattern beats fixing findings one at a time.

Silent degradation

The pipeline's stated design is "abort and alert rather than ship a hollow edition", but many paths still swallow failure: zero-sends exit 0, pagination errors return partial data, LLM responses missing batch items become "unscored" (invisible to the 50% abort check), GitHub secondary-rate-limit 403s return empty lists, Groq 5xx isn't retried. Each one ships a thin or broken edition with only a log line to notice.

Re-runs aren't safe — but the recovery playbook is a re-run

CLAUDE.md's missed-send recovery says "run it again", yet re-running double-sends to everyone before a mid-send crash, duplicates the edition row in the archive, re-sends reminders when the Baserow marker PATCH failed, and inflates the admin email's sent-count (same-day log grep). Idempotency markers (edition-sent flag, existing-row check) would make the documented recovery actually safe.

Untrusted content flows to subscribers

RSS titles/summaries, READMEs, and release bodies are interpolated raw into LLM prompts, and the model's output lands in inboxes — a compromised feed or repo can steer tier/copy (prompt injection). Autoescaping handles markup, but URL schemes are never validated (javascript: from a hostile feed survives into both email and landing page), and LLM output (tier, relevance) is written to Baserow unvalidated.

The privacy promise has drifted

The policy claims no IP collection and names only Resend, but Turnstile loads on every landing-page view and the app POSTs visitor IPs to Cloudflare siteverify; subscriber emails are also printed to indefinitely-kept logs (the "30-day retention" comment prunes nothing). The fixes are easy: name Cloudflare as a processor, drop the optional remoteip field, actually prune logs.
